# Phase 4l — Plan covers: crop to the subject, not the centre (owner: "the way you cropped the assets under plans is kinda mid")
Worktree: `git worktree add ../scroll-the-quran-4l -b phase4/4l-cover-focal` from `main`. Simulator: ONLY ScrollSim-3d `79A01D58-9B43-456D-A6B6-ABEA6D59C873` (`SCROLL_SIM=<udid>`); shut it down when done.
Owns: `Packages/ScrollKit/Sources/FeatureHome/PlanCoverArtwork.swift` (+ a new `PlanCoverFocal.swift` next to it if you prefer), `Packages/ScrollKit/Sources/FeatureHome/{TodaysReadingCard,ReadingPlansSheet,PlanDetailSheet}.swift` (only the cover call sites), `Artwork/tools/covers-from-src.sh` (only if you choose the pipeline route), `Artwork/README.md`, `Tools/snapshot/thresholds.json` + `Reference/scores.md` (plans-sheet / plan-detail / home rows), tests under `Packages/ScrollKit/Tests/FeatureHomeTests`.

## The problem
The 18 covers in `Artwork/src/covers/*.png` (1536×1024, 3:2) were generated to `docs/design/asset-prompts.md`, which put every subject **off-centre in the lower-left or lower-right third** so a title could sit over a calm top. The app then shows them in three crops that ignore that: a 173.5 pt **square** tile in the plans grid (`ReadingPlansSheet`, `PlanCard`), 125/133 pt squares on Home's "Today's Reading" and the active-plan row, and a 1.95:1 hero in `PlanDetailSheet`. `PlanCoverImage` uses `.scaledToFill()` clipped at the centre, so the lantern is sliced at the left edge, the mushaf hangs off the right edge, the crescent (upper-right by design) is cropped out, etc. Look at `.build/snapshots/plans-sheet.png` first.

## Deliver
1. **A per-cover focal point.** For each of the 18 slugs, look at the source PNG (Read the image) and choose the crop anchor that keeps the subject whole and pleasingly placed: a `UnitPoint`-style pair `(x, y)` in 0…1 for the square crops, and a vertical anchor for the 1.95:1 hero. Put the table in `PlanCoverArtwork` (`static let focal: [String: Focal]`), documented per slug in one line ("lantern: subject lower-left → anchor (0.18, 0.62)"). Default `(0.5, 0.5)` for unknown slugs.
2. **Apply it.** `PlanCoverImage` takes the focal point: `Image.resizable().scaledToFill()` inside a `GeometryReader`/`.frame(width:height:alignment:)` + `.clipped()` so the overflow is trimmed on the side away from the subject (compute the offset from the anchor: `offset = (container − scaled) * anchor`). The scrim stays full-frame. Both aspect crops (square and hero) use the same table; the hero uses only the vertical component with x centred unless a slug says otherwise.
3. **Proof.** Before touching the app, build a contact sheet with `magick` in your scratchpad: all 18 covers as (a) the current centre square crop, (b) your focal square crop, (c) the hero crop, labelled by slug; Read it and iterate until every subject is whole. Save the final sheet as `docs/design/cover-crops-contact.jpg` (≤ 1.5 MB) so the owner can review it.
4. **Optional pipeline route.** If code-side alignment cannot reach a good crop for a slug (e.g. it needs a slight zoom), extend `covers-from-src.sh` to emit that slug with a `-gravity`/`-extent` offset instead; keep the shipped size 1200×800 and the JPEG budget. Prefer the code route: one asset per slug.
5. **Tests.** Every slug in `PlanCoverArtwork.slugs` has a focal entry; every anchor is within 0…1; the offset maths is unit-tested for a 3:2 image into a square and into 1.95:1 at the three anchors (0, 0.5, 1).
6. **Gate.** `cd Packages/ScrollKit && swift test --filter FeatureHomeTests`, then `SCROLL_SIM=… SCROLL_CAPTURE_SETTLE=12 Tools/verify.sh --snap plans-sheet plan-detail home-dark` (`plans-sheet` needs the 12 s settle on a cold sim). Read each capture next to `Reference/`, report RMSE before → after (plans-sheet was 0.1995 ≤ 0.22, plan-detail 0.1584 ≤ 0.17; both are accepted deviations because our covers are photographs, so the number may move either way — what matters is the capture looks right; record the new numbers in `Reference/scores.md` and adjust `thresholds.json` only if a capture you have looked at and approved is over).
