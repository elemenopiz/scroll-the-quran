# Phase 4g — Sign in with Apple reaches the user store (audit SEC-2)
Owns: `App/RootView.swift` (the onboarding call site only; orchestrator-approved exception to the App/ freeze), `Packages/ScrollKit/Sources/FeatureOnboarding/{FeatureOnboardingModule,OnboardingModel,OnboardingStores}.swift`, `Packages/ScrollKit/Sources/UserState/{StoreProtocols.swift,UserStore+Actions.swift,Prefs.swift}` (account fields only), `Packages/ScrollKit/Sources/FeatureHome/SettingsView.swift` (account row only), `Widget/**` (optional display-name read), matching tests, `UITests/OnboardingFlowTests.swift`, `docs/store/audit-findings.md` (tick SEC-2 and the Keychain note). Simulator: ONLY `ScrollSim-3d`.
Prereq: Phase 4d merged (Keychain sink `KeychainAccountSink` / `SystemKeychain` exist in `OnboardingStores.swift`).

Problem (audit SEC-2, HIGH): onboarding's Sign in with Apple writes only to `FeatureOnboarding.OnboardingAccountSink` (now Keychain-backed). Nothing calls `UserStore.signIn(accountID:email:)`, so `SettingsView` reads `UserStore` and shows "Not signed in" forever. A reviewer testing Sign in with Apple will see it.

Deliver:
1. **Composite sink.** `FeatureOnboardingModule.view(forScreenID:onFinished:)` gains an `account: any OnboardingAccountSink` parameter (default stays the Keychain sink for previews/screenshots). Add a `CompositeAccountSink` in FeatureOnboarding that forwards the identity (Apple user id, full name) to `KeychainAccountSink` and the sign-in state to a second, minimal protocol the shell can satisfy with `UserStore`: `isSignedIn` flag + display email only. Do NOT write the Apple user identifier into `UserStore`/`prefs.json` (that would undo SEC-1); adjust `UserState.AccountSink.signIn(accountID:email:)` so the shell passes a non-identifying value or add `signIn(email:)`; `Prefs.accountID` may become a boolean `isSignedIn` with a one-time migration that drops any stored id. Keep `signOut()` clearing both sides.
2. **Shell wiring.** `App/RootView.swift` passes the composite built from `env.user` and `KeychainAccountSink(keychain: SystemKeychain(accessGroup: "group.com.scrollthequran"))`. Use the App Group id as the Keychain access group (valid without a `keychain-access-groups` entitlement since iOS 8); verify a write+read round trip in a unit test with `InMemoryKeychain` and, on the simulator, that the value survives relaunch.
3. **Settings.** The account row reads the flag + display email from `UserStore` and shows the signed-in state; "Sign out" clears both sinks. Keep every identifier.
4. **Widget (optional).** If cheap, read the display name from the shared Keychain group for the greeting; otherwise leave and note.
5. **Tests.** Unit: composite forwards correctly, migration drops a stored id, sign-out clears both. XCUITest in `UITests/OnboardingFlowTests.swift`: complete onboarding with the fixture sign-in (`--signed-in` or equivalent launch option; add one in `AppShell/LaunchOptions.swift` if none exists, the only AppShell edit allowed), open Settings, assert the account row shows signed in; sign out; assert "Not signed in".
6. Gate: `SCROLL_SIM=… SCROLL_CAPTURE_SETTLE=6 Tools/verify.sh --ui --snap onboarding-signin home-dark` PASS.

DoD: Settings reflects Sign in with Apple; no Apple identifier in `prefs.json`; SEC-2 ticked in `docs/store/audit-findings.md` with the commit; verify PASS; sim shut down.
